# 受付報告

院長・阿比留さん・片山さんの3人が同じページを見て、報告・相談とその返事を
やり取りするためのシステムです。受付がその場で上げた報告に院長が返し、
1日の終わりにその日のまとめを残します。

**アプリ**: https://claude.ai/artifact/St9NAWan1niW27azwX2HRK
**使いかたページ**: https://claude.ai/artifact/RJkWetZmdpHfdRiW2rrSZ4 （`guide.html`）
**アラート設定ガイド**: `alert-setup.html`（公開版は削除済み。必要なら再公開します）

以前の「受付メモ」と同じアーティファクトを作り替えたものなので、
ホーム画面に置いたアイコンや古いリンク（`claude.ai/code/artifact/d1988dc7-…`）からも
そのまま開けます。

## はじめの設定

3人とも同じ Google アカウント（hakata.stella@gmail.com）でログインして使うため、
**ページ側では誰が開いているか分かりません**。そこで、端末ごとに一度だけ名前を選びます。

1. それぞれのスマホで上のURLを開く
2. 「この端末はどなたですか？」で **院長 / 阿比留 / 片山** から自分を選ぶ
3. ホーム画面に追加しておく（次からは1タップ）

選んだ名前はその端末に保存され、次からは聞かれません。右上のボタンでいつでも
切り替えられるので、共用のPCなど複数人が触る端末でも使えます。

名前を増やす・変えるときは `index.html` 冒頭の `MEMBERS` を直します。

## 使いかた

下の入力欄に打って ↑ で送るだけです。宛先やチェックはありません。
**送ったものは全部、院長の確認待ち**になります。

- 送った時点で **院長 未確認**
- 院長が「確認しました」を押すと **✓ 院長 確認済み**
- 付け加えることがあるときだけ、院長が「ひとこと返す」で返信できます（返信すると確認済みにもなります）

カードには **送った人の名前と日付** が出ます。時刻は出しません。

### 添付

入力欄の左のクリップから、**写真・PDF・動画**を1件につき4つまで貼れます。

- 貼れる形式: JPEG / PNG / WebP / GIF / PDF / MP4 / WebM（1つ20MBまで）
- Excel・Word・テキスト・ZIP は保存領域が受け付けないので貼れません
- 写真は送信前に長辺1600pxへ縮小し、JPEG品質0.82で送ります
  （実測: 4000×3000の10MB → 0.65MB、94%減）
- カードのサムネイルをタップすると全画面で見られます
- 報告を削除すると、その添付も保存領域から消えます

### 消しかた

誤って入力したときは **削除** を2回押します。1回目で「もう一度で削除」に変わり、
3秒さわらなければ元に戻ります。消せるのは自分が書いたものだけです。

- 報告 — カード右下の「削除」
- 院長のひとこと — 返信の右上の「削除」
- 今日のまとめ — まとめカードの「削除」

消したものは、相手の端末に控えが残っていても復活しません。

### タブ

- **未確認** — まだ相手が確認していないものだけ。件数が出て、0でなければ色が付きます。3人とも同じ数を見ます
- **すべて** — 全部の履歴を、新しい日が上に来る順で
- **今日** — 今日のぶんだけ

院長から受付への連絡を送ったときは、受付が確認するまで「受付 未確認」と出ます。

### 1日のまとめ（日報）

今日の欄の先頭に「＋ 今日のまとめを書く」が出ます（受付のみ）。
来院数や気づいたことを書いておくと、その日のカードとして残り、院長からも読めます。

## 状態の見かた

| 表示 | 意味 |
|---|---|
| 院長 未確認 | 院長がまだ見ていない。未確認タブに残る |
| ✓ 院長 確認済み | 院長が「確認しました」を押した |
| 受付 未確認 | （院長の投稿）受付がまだ見ていない |

## 保存のしくみ

- 送信・確認・返信・完了のたびに、このページ自身が新しいバージョンとして保存されます
- **開いている相手の画面は、保存に合わせて更新されます**。院長が開いたままなら報告はそのまま届きます
- 端末側にも控えを持つので、電波が悪くても入力は消えません。つながったときに保存されます
- 3人が同時に書いても、投稿単位・返信単位で突き合わせて統合するので取りこぼしません
- ヘッダーの表示が保存状態です（保存済み／保存中…／保存できません／この端末のみ／閲覧のみ）

### リアルタイム同期（db）を使っていない理由

この環境では `db` 機能（ページ外にデータを置いて即時同期する仕組み）も使えますが、
db を使うページは同じ組織のメンバーしか開けないという制約があります。
3人が同じアカウントで使う今の運用なら db でも動きますが、将来それぞれのアカウントに
分ける可能性を考えて、組織外の人を招待しても動く現在の方式にしています。
アカウントを分けない方針が固まれば、db 方式に切り替えて
リロードなしの即時反映にできます。

## 毎朝の未確認アラート

院長がまだ確認していない報告が残っていると、**毎朝 8:17（日本時間）にメールが届きます**。
0件の日は送りません。

**止まる条件はひとつだけ、院長が「確認しました」を押すことです。** 押さないかぎり、
何日でも毎朝届き続けます。放置が長くなるほど件名を強くします。

| 経過 | 件名 |
|---|---|
| 1日目 | `📋 受付から 未確認N件｜確認おねがいします` |
| 2日目 | `⏰ 受付から 未確認N件｜2日目｜確認おねがいします` |
| 3日目以降 | `🔴 受付から 未確認N件｜N日目｜まだ確認がついていません` |

経過日数は、いちばん古い未確認の報告の `createdAt` から今日までの日数（JST）です。

- スケジュールタスク名: `受付報告の未確認アラート（確認がつくまで毎朝）`
- 中身: アプリのページを読み、`ack` が無くて `by` が `inchou` 以外、かつ `deleted` に
  入っていない報告を数え、1件以上なら日付・名前・本文を並べたメールを送る
- 添付のある報告は行末に `（添付あり）` が付く
- 宛先: `hakata.stella@gmail.com`（3人で共用しているアカウント。変更の指示があるまでここ固定）
- 8:30 ではなく 8:17 なのは、定期実行が毎時0分・30分に集中して遅れやすいためです

1日の回数を増やす（朝・昼・夕など）ことも、時刻を変えることもできます。

### 送信経路の変更（2026-10-19）

最初は「毎回あたらしいセッションを立ち上げて実行する」形で作りましたが、
**この形のタスクには Gmail コネクタが付かない**（作成時に警告が出る）ため、
10/18・10/19 の実行は成功扱いなのに**メールが1通も出ませんでした**。

そこで、**この作業セッション自身を起こす形**（persistent session）に作り替えました。
このセッションは Gmail コネクタを持っているので、`mcp__Gmail__send_message` で
直接1通送れます。10/20 の実行から実際にメールが届いています。

弱点は、このセッションが将来止まったときに一緒に止まることです。
止まっても警告は出ないので、未確認が残っているはずなのにメールが来ない日が
2日続いたら教えてください。恒久的にしたい場合は、claude.ai の定期タスク画面から
同じ内容のタスクを作り直して **Gmail コネクタを紐付ける**のが一番確実です。
手順とプロンプトは `alert-setup.html` にまとめてあります
（公開していたページは削除されたので、必要になったら再公開します）。

環境変数 `GMAIL_CLIENT_ID` / `GMAIL_CLIENT_SECRET` / `GMAIL_REFRESH_TOKEN`
（GitHub Actions に入っているものと同じ）を設定して
[`tools/notify_unconfirmed.py`](../tools/notify_unconfirmed.py) を使う方法も残してあります。
単体でも動き、送信せずに本文だけ確認できます。

```bash
python3 tools/notify_unconfirmed.py state.json --dry-run
```

## アカウントについて

3人が同じ Google アカウントを共用するため、**このアカウントで作ったものは
全員が見られます**（他のアーティファクト、チャット履歴を含む）。
給与や人事に関わるものを同じアカウントに置く場合は、その前提でお使いください。
分けたい場合は、院長だけ別アカウントにして共有メニューから編集権限で招待する形にもできます。

## 開発メモ

`index.html` がアプリ本体、`guide.html` が3人に渡す使いかたページです。
アプリの挙動を変えたときは `guide.html` も合わせて直してください。

`index.html` が本体です（1ファイル完結、外部依存は Google Fonts のみ）。
状態はページ内の `<script id="app-state">` に JSON で埋め込まれ、保存時はページ自身の
公開ソースを取得してこのブロックだけを差し替えて再公開します。

投稿は `by`（メンバーID）、確認は `ack`（時刻）と `ackBy`（押した人）を持ちます。
`MEMBERS` の `side`（director / reception）が、誰が確認する側かを決めます。
初期版の `from` / `needsReply` / `closedAt` も読み飛ばせるようにしてあります。

更新するときは同じファイルを再公開すればURLは変わりません。**再公開の前に必ず
公開中の版を読み、その時点の `app-state` を新しいファイルに引き継いでください。**
引き継がずに公開すると、やり取りの履歴が消えます。
