# 受付報告

受付と院長が同じページを見て、報告・相談とその返事をやり取りするためのシステムです。
受付がその場で上げた報告に院長が返し、1日の終わりにその日のまとめを残します。

**公開URL**: https://claude.ai/artifact/St9NAWan1niW27azwX2HRK

以前の「受付メモ」と同じアーティファクトを作り替えたものなので、
ホーム画面に置いたアイコンや古いリンク（`claude.ai/code/artifact/d1988dc7-…`）からも
そのまま開けます。

## 使いかた

1. 初めて開くと「どちらですか？」と聞かれるので、**受付** か **院長** を選びます
   （端末ごとに1回だけ。右上のボタンでいつでも切り替えられます）
2. 下の入力欄に打って ↑ で送る
3. 返事や対応が必要なものは **「返事がほしい」**（院長側は「対応してほしい」）を付ける
4. 相手の画面には、各カードの **確認 / 返信 / 完了** のボタンが出ます

### 役割で変わるところ

| | 受付 | 院長 |
|---|---|---|
| 入力欄 | 報告・相談を入力 | 指示・連絡を入力 |
| チェックの意味 | 返事がほしい | 対応してほしい |
| 「要対応」に入るもの | 院長からの指示（完了にするまで）／自分の報告に返信がきたもの | 未読の報告／返事がまだの相談 |

院長の相談は**返信すれば片づき**、院長からの指示は**「完了」を押すまで**受付の要対応に残ります。
やることと、答えればいいことの違いに合わせてあります。

### タブ

- **すべて** — 全部の履歴を、新しい日が上に来る順で
- **要対応** — いま自分が動くべきものだけ。件数が出ます
- **今日** — 今日のぶんだけ

### 1日のまとめ（日報）

今日の欄の先頭に「＋ 今日のまとめを書く」が出ます（受付のみ）。
来院数や気づいたことを書いておくと、その日のカードとして残り、院長からも読めます。

## 状態の見かた

| 表示 | 意味 |
|---|---|
| 未読 | 相手がまだ見ていない |
| 確認済み | 相手が「確認」を押した |
| 要返事 / 対応おねがい | 返事または対応が必要 |
| 返事待ち / 未対応 | まだ返ってきていない |
| 返信あり | 返事がついた |
| 完了 | この件は終わり（「戻す」で開き直せます） |

## 保存のしくみ

- 送信・確認・返信・完了のたびに、このページ自身が新しいバージョンとして保存されます
- **開いている相手の画面は、保存に合わせて更新されます**。院長が開いたままなら報告はそのまま届きます
- 端末側にも控えを持つので、電波が悪くても入力は消えません。つながったときに保存されます
- 2人が同時に書いても、投稿単位・返信単位で突き合わせて統合するので取りこぼしません
- ヘッダーの表示が保存状態です（保存済み／保存中…／保存できません／この端末のみ／閲覧のみ）

### リアルタイム同期（db）を使っていない理由

この環境では `db` 機能（ページ外にデータを置いて即時同期する仕組み）も使えますが、
**db を使うページは同じ組織のメンバーしか開けません**。院長が別アカウントの場合に
院長だけ使えなくなるため、組織外の人を招待しても動く現在の方式を採っています。
受付と院長が同じワークスペースに入るなら、db 方式に切り替えると
リロードなしの即時反映にできます。

## スタッフへの共有

ページ右上の共有メニューから。**編集権限**を渡した人だけが書き込めます。
閲覧のみの人には入力欄が出ず、「閲覧のみ」と表示されます。

## 開発メモ

`index.html` が本体です（1ファイル完結、外部依存は Google Fonts のみ）。
状態はページ内の `<script id="app-state">` に JSON で埋め込まれ、保存時はページ自身の
公開ソースを取得してこのブロックだけを差し替えて再公開します。

更新するときは同じファイルを再公開すればURLは変わりません。**再公開の前に必ず
公開中の版を読み、その時点の `app-state` を新しいファイルに引き継いでください。**
引き継がずに公開すると、やり取りの履歴が消えます。
